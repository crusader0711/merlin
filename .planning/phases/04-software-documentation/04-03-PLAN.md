Create `03_software/04_usb_protocol.md` following conventions.md document template. Ensure `03_software/` directory exists.

**Document structure:**

1. **Header** -- Purpose: Specify the USB interface protocol completely enough to implement a new client. Prerequisites.

2. **Protocol Overview** -- Three communication paths:
   - FPGA -> Host PC: Radar data via FT601 USB 3.0 (bulk transfer)
   - STM32 -> Host PC: GPS/settings via USB CDC (virtual COM port)
   - Host PC -> STM32: Start/stop commands via USB CDC

3. **FT601 Physical Layer** -- FT601 Slave FIFO mode. Clock: `ft601_clk_in` (100 MHz, asynchronous to system 100 MHz -- separate oscillator per Phase 3 decision). 32-bit bidirectional data bus with tri-state control. Flow control signals: `ft601_txe` (TX FIFO empty), `ft601_rxf` (RX FIFO full). Reference `02_hardware/05_fpga_board.md` for FT601 clock domain details.

4. **FPGA-to-Host Packet Format** -- From `usb_data_interface.v` state machine:

```
State Machine: IDLE -> SEND_HEADER -> SEND_RANGE_DATA -> SEND_DOPPLER_DATA ->
               SEND_DETECTION_DATA -> SEND_FOOTER -> WAIT_ACK -> IDLE
```

Packet structure table:
| Field | Size | Byte Enable | Content |
|-------|------|-------------|---------|
| Header | 8-bit | BE=01 | 0xAA |
| Range profile | 4x 32-bit | BE=11 | Range bin magnitudes |
| Doppler data | 4x 32-bit | BE=11 | Packed {Q[15:0], I[15:0]} |
| Detection flag | 8-bit | BE=01 | {7'b0, cfar_detection} |
| Footer | 8-bit | BE=01 | 0x55 |

Document byte ordering, total packet size, and expected data rate.

5. **STM32-to-Host Protocol** -- GPS binary data format from `GPS_SendBinaryToGUI()` in main.cpp. RadarSettings structure from `RadarSettings.h`. Document `parseFromUSB()` method for settings parsing. Start flag protocol via `isStartFlagReceived()`.

6. **Host-to-STM32 Commands** -- Document command format for start/stop radar operation and any settings updates sent from GUI to STM32.

7. **Streaming Protocol** -- How continuous data streaming works: FPGA sends packets at chirp rate, FT601 buffers, host reads in bulk. Document expected throughput and any flow control mechanisms.

8. **Implementing a New Client** -- Brief section summarizing what a developer needs: open FT601 device, configure for Slave FIFO, read packets, parse header/footer, extract range/Doppler/detection data.

9. **References** -- Symbol table, FPGA pipeline doc, hardware docs.

**Formatting:** Use SW-tagged equations only if mathematical derivations are needed (e.g., data rate calculations). Pair all code variable names with descriptions per conventions.md anti-pattern 5.4.
