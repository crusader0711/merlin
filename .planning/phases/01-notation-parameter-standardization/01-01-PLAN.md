  <files>00_notation/conventions.md</files>
  <action>
Create `00_notation/conventions.md` with the following sections:

**1. Document Purpose** -- One paragraph: this file is the single source of truth for how all project documents format equations, reference other documents, and present mathematical content.

**2. Equation Numbering Convention** -- Use document-prefix scheme to avoid cross-document collisions (as identified in research Pitfall 5):
  - Assign a unique prefix per future document. Define the mapping:
    - FMCW theory: `FMCW-N` (e.g., Eq. (FMCW-1), Eq. (FMCW-2))
    - LFM waveform: `LFM-N`
    - Beamforming: `BF-N`
    - Detection theory: `DET-N`
    - Noise figure: `NF-N`
    - Calibration: `CAL-N`
    - Hardware docs: `HW-N` (with subsection prefix if needed, e.g., `HW-RF-N`)
    - Software docs: `SW-N`
  - Show the MathJax syntax: `$$\n R = \frac{c \cdot f_b}{2\mu} \tag{FMCW-1}\n$$`
  - State explicitly: Every equation that is referenced anywhere MUST have a `\tag{}`. Unreferenced display equations MAY omit tags.

**3. Cross-Reference Format** -- Define the plain-text convention (since `\ref{}` and `\eqref{}` do NOT work on GitHub):
  - Within same document: "see Eq. (FMCW-3)" (plain text, no MathJax)
  - Cross-document: "Eq. (FMCW-3) in [`physics/01_fmcw_theory.md`](../physics/01_fmcw_theory.md#section-heading)"
  - Use Markdown heading anchors for deep links

**4. MathJax Usage Rules for GitHub** -- Document what works and what does NOT:
  - SUPPORTED: `$...$` inline, `$$...$$` display, `\tag{}`, `\text{}`, `\frac{}{}`, `\left(\right)`, standard LaTeX math
  - NOT SUPPORTED: `\ref{}`, `\eqref{}`, `\label{}`, automatic numbering (`tags: 'ams'`), `\begin{align}` with auto-numbering
  - Unit formatting standard: `$f_c = 10.5~\text{GHz}$` (tilde for non-breaking space, `\text{}` for upright units)
  - Multi-line equations: Use `\begin{aligned}...\end{aligned}` inside `$$...$$` with a single `\tag{}` on the block

**5. Variant Callout Block** -- Define the standard admonition format for when Nexus and Extended values differ:
```
> **Variant Note:**
> | | Nexus | Extended |
> |--|-------|----------|
> | parameter | value | value |
```

**6. Anti-Patterns** -- List from research:
  - Never inline parameter values in derivations (keep symbolic; values in parameter_table.md only)
  - Never define the same parameter value in two places
  - Never use different symbols for the same concept across documents
  - Never use raw codebase variable names (e.g., `T1`, `PRI1`) in physics/hardware docs without the standard symbol

**7. Document Template** -- Provide a skeleton that all future documents should follow:
  - Title, purpose, prerequisites (links to symbol_table and parameter_table)
  - Section with derivations using `\tag{PREFIX-N}`
  - Variant callout blocks where applicable
  - References section
