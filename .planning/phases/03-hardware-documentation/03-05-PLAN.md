Structure:
1. **Overview** -- Timing budget purpose: trace latency from antenna to display for understanding system responsiveness and identifying bottlenecks.

2. **Chirp Sequence Timing** (critical -- Pitfall 7 from research) --
   - Per-beam-position sequence documented from `executeChirpSequence()` in main.cpp:
     - 16 long chirps at $T_{r,1} = 167~\mu\text{s}$ each (total: $16 \times 167 = 2672~\mu\text{s}$)
     - Guard time: $T_\text{guard} = 175.4~\mu\text{s}$
     - 16 short chirps at $T_{r,2} = 175~\mu\text{s}$ each (total: $16 \times 175 = 2800~\mu\text{s}$)
   - Total per beam position equation: $T_\text{pos} = \frac{M}{2} T_{r,1} + T_\text{guard} + \frac{M}{2} T_{r,2}$ (HW-TIM tag)
   - Numerical: $T_\text{pos} = 2672 + 175.4 + 2800 = 5647.4~\mu\text{s}$ (note: this is a worked example referencing parameter_table.md, not an inlined derivation)
   - Map firmware variables: `m_max` -> $M$, `T1` -> $T_{c,1}$, `PRI1` -> $T_{r,1}$, etc.

3. **Full Scan Timing** --
   - Per revolution: $N_\text{el} = 31$ elevation positions per azimuth, $N_\text{az} = 50$ azimuth positions
   - Elevation scan time: $T_\text{el} = N_\text{el} \times T_\text{pos}$ (HW-TIM tag)
   - Stepper motor: 200 steps/rev, 4 steps per azimuth position, 1ms per step (500us high + 500us low) -> 4ms per azimuth move
   - Full revolution time: $T_\text{rev} = N_\text{az} \times (T_\text{el} + T_\text{step})$ (HW-TIM tag)
   - Compute approximate revolution time for context

4. **FPGA Pipeline Latency** --
   - Stage-by-stage latency analysis through the signal processing chain:
     - ADC capture (400 MHz domain): sample acquisition time
     - CDC crossing (400 -> 100 MHz): synchronizer latency (~3 clock cycles at 100 MHz)
     - DDC (digital downconversion): NCO mixing latency
     - CIC decimation (5-stage, 4x): group delay from CIC filter
     - Matched filter (1024-pt): buffer fill + processing
     - FFT (1024-pt): full transform latency
     - Doppler processor (32-pt FFT, 64 range bins): accumulation across M chirps + processing
     - CFAR detection: reference cell accumulation + threshold
     - USB output (FT601 domain): packetization and transfer
   - For each stage: estimate latency in clock cycles and time. Note where estimates are theoretical (requires Vivado timing report for actual values).
   - Total pipeline latency equation: $t_\text{pipeline} = \sum_i t_{\text{stage},i}$ (HW-TIM tag)

5. **End-to-End Latency Summary** -- Table with each latency contributor: chirp acquisition, FPGA processing, USB transfer, PC processing. Total time from "target illuminated" to "target displayed on GUI."

6. **References** -- parameter_table.md, FPGA board doc, frequency synthesis doc (clock rates), main.cpp.

Create `02_hardware/09_gps_imu_transforms.md` with `HW-NAV-` equation prefix following conventions.md template.

Structure:
1. **Overview** -- Navigation subsystem purpose: convert radar-relative detections (range, azimuth angle, elevation angle) into GPS-absolute coordinates for map display. Components: GY-85 IMU (3-axis accel, gyro, magnetometer), BMP180 barometer, GPS via TinyGPS++ on UART5.

2. **GY-85 IMU Sensors** --
   - ADXL345 accelerometer: I2C address 0x53, 3-axis acceleration
   - ITG3200 gyroscope: I2C address 0x68, 3-axis angular rate
   - HMC5883 magnetometer: I2C address 0x1E, 3-axis magnetic field
   - Document I2C initialization from GY_85_HAL driver

3. **Attitude Estimation: Complementary Filter** --
   - Document from main.cpp lines ~1280-1385
   - Pitch from accelerometer: $\theta_\text{pitch} = \arctan\!\left(\frac{a_x}{\sqrt{a_y^2 + a_z^2}}\right)$ (HW-NAV tag)
   - Roll from accelerometer: $\theta_\text{roll} = \arctan\!\left(\frac{a_y}{\sqrt{a_x^2 + a_z^2}}\right)$ (HW-NAV tag)
   - Complementary filter fusion (50/50 accel/gyro weighting from firmware):
     $\theta_\text{fused} = \alpha \cdot \theta_\text{accel} + (1 - \alpha) \cdot (\theta_\text{prev} + \omega \cdot \Delta t)$ with $\alpha = 0.5$ (HW-NAV tag)
   - Map firmware variables to standard symbols

4. **Magnetometer and Yaw** --
   - Tilt-compensated magnetometer heading from firmware
   - Calibration: 3x3 rotation matrix (M11-M33) and bias correction (HW-NAV equation for calibration transform)
   - Magnetic declination correction: $-0.61^\circ$ (from `Mag_Declination` in main.cpp, reference parameter_table.md)
   - Yaw computation from tilt-compensated magnetic field components (HW-NAV tags)

5. **Barometric Altitude** --
   - BMP180 pressure sensor
   - Hypsometric formula: $h = \frac{T_0}{L} \left[\left(\frac{P_0}{P}\right)^{R_\text{air}L/gM_\text{air}} - 1\right]$ or the simplified version used in firmware (HW-NAV tag)

6. **Radar-to-World Coordinate Transform** --
   - Radar frame: target at (range $R$, azimuth $\phi_\text{az}$, elevation $\theta_\text{el}$)
   - Body frame: apply pitch/roll/yaw corrections from complementary filter
   - Rotation matrix formulation: $\mathbf{p}_\text{world} = \mathbf{R}_\text{yaw} \mathbf{R}_\text{pitch} \mathbf{R}_\text{roll} \mathbf{p}_\text{radar}$ (HW-NAV tag)
   - Write out the 3x3 rotation matrices explicitly (HW-NAV tags)
   - GPS-absolute position: radar position (lat, lon, alt) + rotated target vector
   - Note: firmware initializes quaternion array `q[4]` but the complementary filter uses Euler angles. Document both representations and which is actually used.

7. **GPS Integration** --
   - TinyGPS++ on UART5: provides latitude, longitude, altitude
   - GPS_Data_t struct fields from main.cpp
   - Coordinate conversion from GPS (lat/lon) + radar-relative target -> absolute target position

8. **References** -- GY-85 datasheet, BMP180 datasheet, symbol_table.md, parameter_table.md, beamforming doc (beam position to angle mapping).
